# Glossary

Terms the documentation uses, the standard each one comes from, and where it is explained.

| Term                       | Meaning                                                                                                        | Standard                                                                                | Explained in                                                                                                              |
|----------------------------|----------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------|
| Access token               | Short-lived JWT (five minutes) that authorizes one API request.                                                | [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-1.4) §1.4                     | [Authentication: Every request is authorized by a token](docs/authentication.md#every-request-is-authorized-by-a-token)   |
| Adapter                    | An `infrastructure` implementation of a port: HTTP, Toasty, Keycloak, Redis, the file system.                  | —                                                                                       | [Architecture: A modular monolith with hexagonal modules](docs/architecture.md#a-modular-monolith-with-hexagonal-modules) |
| Audience (`aud`)           | The token claim naming who the token is for; a token for another audience is refused.                          | [RFC 7519](https://www.rfc-editor.org/rfc/rfc7519#section-4.1.3) §4.1.3                 | [Authentication: Every request is authorized by a token](docs/authentication.md#every-request-is-authorized-by-a-token)   |
| Authorization code flow    | Sign-in by redirecting to Keycloak and exchanging the returned code for tokens on the server.                  | [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-4.1) §4.1                     | [Authentication: Signing in](docs/authentication.md#signing-in)                                                           |
| BFF (backend for frontend) | The server signs the user in and keeps the tokens; the browser holds only a session cookie.                    | —                                                                                       | [Authentication](docs/authentication.md)                                                                                  |
| Composition root           | `src/bootstrap`, the only place that names a concrete adapter.                                                 | —                                                                                       | [Architecture: The composition root](docs/architecture.md#the-composition-root)                                           |
| ICU MessageFormat          | The message syntax of the catalog, with plural rules for Polish.                                               | [ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/) | [Architecture: Errors are message keys](docs/architecture.md#errors-are-message-keys)                                     |
| ID token                   | Token describing who signed in, issued with the access token.                                                  | [OpenID Connect Core 1.0](https://openid.net/specs/openid-connect-core-1_0.html)        | [Authentication: Signing in](docs/authentication.md#signing-in)                                                           |
| JWKS                       | Keycloak's published public keys, used to verify a token's signature.                                          | [RFC 7517](https://www.rfc-editor.org/rfc/rfc7517)                                      | [Authentication: Every request is authorized by a token](docs/authentication.md#every-request-is-authorized-by-a-token)   |
| JWT                        | Signed JSON token; the access token is one.                                                                    | [RFC 7519](https://www.rfc-editor.org/rfc/rfc7519)                                      | [Authentication: Every request is authorized by a token](docs/authentication.md#every-request-is-authorized-by-a-token)   |
| Keycloak realm             | The Keycloak tenant that holds this application's users, roles and clients.                                    | —                                                                                       | [Authentication](docs/authentication.md)                                                                                  |
| Message key                | A key of the translation catalog sent instead of prose; the client renders it in the reader's language.        | —                                                                                       | [Architecture: Errors are message keys](docs/architecture.md#errors-are-message-keys)                                     |
| PKCE                       | A one-time secret that ties the returned code to the browser that started the sign-in.                         | [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636)                                      | [Authentication: Signing in](docs/authentication.md#signing-in)                                                           |
| Port                       | A trait in a module's `application` layer for anything outside it.                                             | —                                                                                       | [Architecture: A modular monolith with hexagonal modules](docs/architecture.md#a-modular-monolith-with-hexagonal-modules) |
| Problem document           | The JSON body of every refusal: status, a message key and its arguments.                                       | [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)                                      | [Architecture: Errors are message keys](docs/architecture.md#errors-are-message-keys)                                     |
| Refresh token              | Long-lived token the server trades for a new access token; Keycloak rotates it on every use.                   | [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-1.5) §1.5                     | [Authentication: Sessions and refreshing](docs/authentication.md#sessions-and-refreshing)                                 |
| Refresh token rotation     | Every refresh returns a new refresh token and invalidates the old one; replaying a spent one ends the session. | —                                                                                       | [Authentication: Sessions and refreshing](docs/authentication.md#sessions-and-refreshing)                                 |
| `SameSite` cookie          | Cookie attribute that keeps the session cookie off cross-site requests.                                        | [RFC 6265bis](https://datatracker.ietf.org/doc/draft-ietf-httpbis-rfc6265bis/) (draft)  | [Authentication: Cross-site requests](docs/authentication.md#cross-site-requests)                                         |
| `Sec-Fetch-Site`           | Header the browser sends to say where a request came from; an unsafe cross-site request gets no token.         | [Fetch Metadata](https://www.w3.org/TR/fetch-metadata/) (W3C)                           | [Authentication: Cross-site requests](docs/authentication.md#cross-site-requests)                                         |
| Sign-out                   | Ends the local session and the Keycloak session.                                                               | —                                                                                       | [Authentication: Signing out](docs/authentication.md#signing-out)                                                         |
| Single-flight refresh      | One refresh per refresh token, shared by every request of the session that needs it at once.                   | —                                                                                       | [Authentication: Sessions and refreshing](docs/authentication.md#sessions-and-refreshing)                                 |
| Soft delete                | Marking a file deleted while keeping its row and its bytes.                                                    | —                                                                                       | [files: Behavior](src/files/README.md#behavior)                                                                           |
| Translation override       | An administrator's text for a key; it survives new defaults until it is reset.                                 | —                                                                                       | [translations: Defaults and overrides](src/translations/README.md#defaults-and-overrides)                                 |

# Glossary

Every term the documentation uses without defining it on the spot, and where it is explained. The specifications behind
them are in [STANDARDS.md](STANDARDS.md).

| Term                       | Meaning                                                                                                         | Explained in                                                                                                              |
|----------------------------|-----------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------|
| Access token               | Short-lived JWT (five minutes) that authorizes one request.                                                     | [Authentication: Every request is authorized by a token](docs/authentication.md#every-request-is-authorized-by-a-token)   |
| Account action             | A Keycloak page alone, `kc_action`: the password, or turning the second factor on or off.                       | [Authentication: Account actions](docs/authentication.md#account-actions)                                                 |
| Adapter                    | An `infrastructure` implementation of a port: HTTP, Toasty, Keycloak, Redis, S3, the file system.               | [Architecture: A modular monolith with hexagonal modules](docs/architecture.md#a-modular-monolith-with-hexagonal-modules) |
| Audience                   | The `aud` claim naming whom a token is for; a token for anyone else is refused.                                 | [Authentication: Every request is authorized by a token](docs/authentication.md#every-request-is-authorized-by-a-token)   |
| `Auth`, `Permitted`        | The extractors a handler takes to require a signed-in caller, or one whose roles grant a permission.            | [Architecture: Routes](docs/architecture.md#routes)                                                                       |
| Authorization code flow    | Sign-in by redirecting to Keycloak and exchanging the code it returns, on the server.                           | [Authentication: Signing in](docs/authentication.md#signing-in)                                                           |
| Back-end                   | The Axum API behind the front-end; it signs people in, keeps their sessions and holds the data.                 | [Architecture: Two applications](docs/architecture.md#two-applications)                                                   |
| BFF (backend for frontend) | The application signs the user in and keeps the tokens; the browser holds only a session cookie.                | [Authentication](docs/authentication.md)                                                                                  |
| Catalog                    | Every message the application can send, keyed, in Polish and English.                                           | [translations](backend/src/translations/README.md)                                                                        |
| Color theme                | System, Light or Dark, as the reader chooses in the top bar; System follows their system.                       | [front-end: Theme](frontend/README.md#theme)                                                                              |
| Composition root           | `backend/src/bootstrap`, the only place that names a concrete adapter.                                          | [Architecture: The composition root](docs/architecture.md#the-composition-root)                                           |
| Default                    | A message as shipped by a module or the front-end; refreshed at every start.                                    | [Translation catalog](backend/src/translations/docs/mechanisms/translation-catalog.md)                                    |
| Form refusal               | A form the back-end refused, rendered again with its problem and what the reader typed.                         | [front-end: Layout](frontend/README.md#layout)                                                                            |
| Front-end                  | The Topcoat application the browser talks to; it renders the pages and passes the API on.                       | [Architecture: Two applications](docs/architecture.md#two-applications)                                                   |
| Keycloak realm             | The Keycloak tenant holding this application's users, roles and clients.                                        | [Authentication](docs/authentication.md)                                                                                  |
| `lang` cookie              | The language the reader chose in the header; it also picks Keycloak's language.                                 | [front-end: Text](frontend/README.md#text)                                                                                |
| Layer                      | `domain`, `application` or `infrastructure`; dependencies point inward.                                         | [Architecture: A modular monolith with hexagonal modules](docs/architecture.md#a-modular-monolith-with-hexagonal-modules) |
| Message key                | A key of the catalog sent instead of a sentence; the client renders it.                                         | [Error responses](docs/mechanisms/error-responses.md)                                                                     |
| Migration                  | A Toasty schema change in `backend/toasty/migrations`, applied with the `cli` binary.                           | [Development Setup: Migrations](docs/development-setup.md#migrations)                                                     |
| Mirrored account           | The local copy of a Keycloak user, updated whenever the token differs from it.                                  | [identity: Accounts mirror Keycloak](backend/src/identity/README.md#accounts-mirror-keycloak)                             |
| Module                     | `identity`, `keycloak_account`, `files` or `translations`: one hexagon inside the binary.                       | [Architecture: A modular monolith with hexagonal modules](docs/architecture.md#a-modular-monolith-with-hexagonal-modules) |
| Navigation module          | A part of the front-end in the top bar, such as Files or Administration, with its sections.                     | [front-end: Navigation and tables](frontend/README.md#navigation-and-tables)                                              |
| Origin policy              | Topcoat's check that refuses a change or a WebSocket sent from another site, before any route runs.             | [front-end: Changes and cross-site requests](frontend/README.md#changes-and-cross-site-requests)                          |
| Override                   | An administrator's text for a key; it survives new defaults until it is reset.                                  | [Translation catalog](backend/src/translations/docs/mechanisms/translation-catalog.md)                                    |
| Page                       | A Topcoat handler rendering HTML at the URL its module's path gives it.                                         | [front-end: Pages](frontend/README.md#pages)                                                                              |
| Page result                | One part of a collection, `page` from 0 and `size` 1 to 100, answered with its totals.                          | [Architecture: Collections are paged](docs/architecture.md#collections-are-paged)                                         |
| Permission                 | Something one module checks before it acts, declared in that module's catalog.                                  | [Authorization](docs/authorization.md)                                                                                    |
| PKCE                       | A one-time secret binding the returned code to the browser that started the sign-in.                            | [Authentication: Signing in](docs/authentication.md#signing-in)                                                           |
| Port                       | A trait a module's `application` layer owns for anything outside it.                                            | [Architecture: A modular monolith with hexagonal modules](docs/architecture.md#a-modular-monolith-with-hexagonal-modules) |
| Problem document           | The JSON body of every refusal, carrying a message key and its arguments.                                       | [Error responses](docs/mechanisms/error-responses.md)                                                                     |
| Proxy                      | The front-end's routes passing `/api` and `/uploads` on to the back-end, as the browser sent them.              | [front-end: The back-end behind it](frontend/README.md#the-back-end-behind-it)                                            |
| Refresh token              | Long-lived token traded for a new access token; Keycloak rotates it on every use.                               | [Token refresh](backend/src/identity/docs/mechanisms/token-refresh.md)                                                    |
| Refresh token rotation     | Every refresh invalidates the refresh token it used; replaying a spent one ends the session.                    | [Token refresh](backend/src/identity/docs/mechanisms/token-refresh.md)                                                    |
| Role                       | A Keycloak realm role read from the access token, and the permissions it grants here.                           | [Authorization](docs/authorization.md)                                                                                    |
| `Sec-Fetch-Site`           | Header saying where a request came from; an unsafe cross-site request gets no token.                            | [Cross-site requests](backend/src/identity/docs/mechanisms/cross-site-requests.md)                                        |
| Section                    | A page the side bar links to inside a navigation module, such as Roles under Administration.                    | [front-end: Navigation and tables](frontend/README.md#navigation-and-tables)                                              |
| Session                    | `RUST_AXUM_APP_SESSION`, kept in Redis, ending after ten hours without a request.                               | [Token refresh](backend/src/identity/docs/mechanisms/token-refresh.md)                                                    |
| Sign-in theme              | The look Keycloak gives its pages and mails, the front-end's, as `keycloak/themes/rust-axum-app`.               | [Authentication: The sign-in pages](docs/authentication.md#the-sign-in-pages)                                             |
| Sign-out                   | Ends the local session and the Keycloak session.                                                                | [Authentication: Signing out](docs/authentication.md#signing-out)                                                         |
| Signed link                | A URL to one object that carries its own permission and expires: a `PUT` for an upload, a `GET` for a download. | [File storage](backend/src/files/docs/mechanisms/file-storage.md)                                                         |
| Single-flight refresh      | One refresh per refresh token, shared by every request of the session that needs it at once.                    | [Token refresh](backend/src/identity/docs/mechanisms/token-refresh.md)                                                    |
| Soft delete                | Marking a file deleted, recording who and when, while keeping its row and bytes.                                | [File storage](backend/src/files/docs/mechanisms/file-storage.md)                                                         |
| Storage kind               | Where a file's bytes live: `s3`, a bucket, or `local`, a folder; each file keeps the one it was uploaded to.    | [File storage: Two storages](backend/src/files/docs/mechanisms/file-storage.md#two-storages)                              |
| Unrestricted role          | A role holding every permission, also those declared later, such as `admin`.                                    | [Authorization: `unrestricted`](docs/authorization.md#unrestricted)                                                       |
| Upload ticket              | A `pending` file and a signed link for its bytes; the file is listed once its upload is confirmed.              | [File storage: Upload](backend/src/files/docs/mechanisms/file-storage.md#upload)                                          |
